# Per-suite wall-clock seconds, used ONLY to balance shards (FASTPKI_SHARD in run_all.sh).
#
# ⚠️ THIS IS A HINT, NEVER A GATE. Nothing fails because a number here is stale or missing:
# an unknown suite is assumed average, and a wrong number costs a slightly uneven run and
# nothing else. Do not add assertions against it and do not let anything read it as a
# performance budget — the moment it becomes a gate, every legitimate slowdown becomes a red
# run and the file starts getting edited to keep the build green.
#
# Why it exists: round-robin sharding assigns by position in the tier arrays, which knows
# nothing about duration. Measured at 6 shards that put 394s of work in one shard and 157s
# in another, so a third of the fleet sat idle while the run waited on the slowest.
#
# ⚠️ THESE ARE THE WORST DURATIONS OBSERVED, NOT THE TYPICAL ONES, AND THAT IS DELIBERATE.
# Under-estimating a long suite is the expensive mistake: the scheduler packs work in
# beside it and the whole run waits. Over-estimating costs an idle shard and nothing else.
# The first version of this file used typical numbers and made the run SLOWER than the
# round-robin it replaced (7m10s against 6m42s) by recording acme_lifecycle.sh at 154s.
#
